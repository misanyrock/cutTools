# CutTools · 视频整理与交付

原生 SwiftUI macOS 应用，提供音乐卡点、字幕整理、文案创作与视频交付。

## 本机配置与首次运行

### 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | 工程最低部署目标为 macOS 14；其他系统版本仍需实机验证 |
| 处理器 | 当前构建产物为 Apple Silicon（arm64）；Intel 版本未验证 |
| 从源码构建 | Xcode 或包含 macOS SDK、Swift 5.9+ 的 Command Line Tools |
| 音乐卡点、视频处理、粗剪、成片检查 | 本机 FFmpeg；字幕烧录额外要求 FFmpeg 启用 libass / `subtitles` 滤镜 |
| 本地语音转字幕 | FFmpeg、whisper.cpp 的 `whisper-cli` 和 ggml 模型文件 |
| 翻译、完整 AI 写稿 | 本地 Ollama + 已下载模型，或在线模型服务 + API Key，任选一种 |
| FCP 时间线导入 | 另需安装 Final Cut Pro；导入兼容性尚待在目标版本验证 |

字幕编辑、独立 SRT/ASS 导出和写作提纲不需要安装 AI 模型。模型文件与第三方程序未打包进 `.app`；复制到其他 Mac 后仍需配置对应依赖。原始素材应保留在可访问的位置，标记工程与 FCPXML 引用它们，不包含音视频文件。

开发机在 2026-10-29 检查到的环境为 Apple Silicon、macOS 27.2、Xcode 27.1、FFmpeg 9.0.2；这些是实测环境，不是最低版本要求。该 FFmpeg 支持 `cropdetect`，未启用 `subtitles`。

### 2. 获取源码、构建与启动

首次从源码开始时：

```sh
git clone https://github.com/misanyrock/cutTools.git
cd cutTools
xcode-select --install
```

已安装开发工具时跳过安装命令。检查工具链，再构建：

```sh
xcode-select -p
swift --version
./script/build_and_run.sh
```

构建脚本会退出已有 CutTools 进程，重新构建、生成 `dist/CutTools.app`、复制图标、完成本地临时签名并启动。运行前先保存音乐标记工程；文案草稿自动保存于本机。

只构建或运行诊断：

```sh
./script/build_and_run.sh --build
./script/build_and_run.sh --verify
./script/build_and_run.sh --debug
./script/build_and_run.sh --logs
```

`--build` 只生成应用；`--verify` 启动并检查进程；`--debug` 进入 LLDB；`--logs` 查看运行日志。这些是分别按需执行的命令。

当前应用仅做本地临时签名，尚未完成 Developer ID 签名与公证。若在受限自动化环境启动时报 Launch Services `-10827`，可从 Finder 打开 `dist/CutTools.app`。其他 Mac 的系统安全检查与运行兼容性仍需单独验证。

### 3. 配置 FFmpeg

如未安装 Homebrew，先按 [Homebrew 官网](https://brew.sh/) 配置。只使用普通视频处理与音乐分析，可安装：

```sh
brew install ffmpeg
command -v ffmpeg
ffmpeg -version
```

应用依次查找以下位置的 `ffmpeg` / `ffprobe`：

```text
/opt/homebrew/bin/
/usr/local/bin/
/usr/bin/
```

应用当前没有自定义 FFmpeg 路径输入框，也不会读取终端的任意 PATH。将程序安装或链接到上述目录后重启应用；Apple Silicon 的 Homebrew 通常使用 `/opt/homebrew/bin`。

**需要烧录字幕时**，先检查当前版本是否有 `subtitles`：

```sh
ffmpeg -hide_banner -filters 2>&1 | sed -n '/subtitles/p'
```

没有输出即不能烧录；单独安装 `libass` 不会给已经编译好的 FFmpeg 增加滤镜。可按 [Homebrew ffmpeg-full 说明](https://formulae.brew.sh/formula/ffmpeg-full) 安装完整版：

```sh
brew install ffmpeg-full
```

`ffmpeg-full` 为 keg-only，安装后不会自动进入应用查找的目录。若已经安装普通 `ffmpeg`，先解除其链接：

```sh
brew unlink ffmpeg
```

再链接完整版；以下操作会把 Homebrew 的默认 FFmpeg 命令切换为完整版：

```sh
brew link --force ffmpeg-full
command -v ffmpeg
ffmpeg -hide_banner -filters 2>&1 | sed -n '/subtitles/p'
```

确认命令位置属于应用查找的目录，且检查结果包含 `subtitles`，再重启 CutTools。其他工具若调用同一 FFmpeg 路径，也会使用新版本。暂时不配置 libass 时，仍可导出独立 ASS/SRT 字幕。

### 4. 配置本地语音转字幕（可选）

参考 [whisper.cpp 官方仓库](https://github.com/ggml-org/whisper.cpp)，在项目外的独立目录安装；不需要把程序或模型提交进 CutTools 仓库。以下从你选定的工具存放目录执行：

```sh
brew install cmake
git clone https://github.com/ggml-org/whisper.cpp.git
cd whisper.cpp
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j 4
sh ./models/download-ggml-model.sh base
./build/bin/whisper-cli --help
```

在 CutTools 的「创作与检查 → AI 字幕」配置：

| 字段 | 选择内容 |
| --- | --- |
| whisper-cli 路径 | 上述目录中的 `build/bin/whisper-cli` 可执行文件 |
| ggml 模型文件 | 上述目录中的 `models/ggml-base.bin`，或其他已下载的兼容模型 |
| 原语言 | 与素材一致的中文或英文 |

`base` 为多语言入门模型；中文不要选择名字带 `.en` 的纯英文模型。更大的模型会增加下载量、内存占用与运行时间，按机器能力选择。模型文件保持原位；移动后需在应用中重新选择路径。配置并保存后，选择视频，再点击转写。

### 5. 配置本地 Ollama（可选）

从 [Ollama 官方 macOS 下载页](https://ollama.com/download/mac) 安装并打开应用，完成命令行工具设置后检查：

```sh
command -v ollama
ollama pull qwen3:8b
ollama list
curl --max-time 10 http://127.0.0.1:11434/api/tags
```

`qwen3:8b` 是 CutTools 的默认示例模型，也可换成已下载的其他中文文本模型；模型大小应与本机可用内存匹配。若本机服务未启动，可打开 Ollama 应用，或在独立终端运行 `ollama serve`；已有服务运行时无需重复启动。具体安装与运行方式见 [Ollama 官方快速开始](https://docs.ollama.com/quickstart)。

在「CutTools → Settings…」（⌘,）选择「本地 Ollama」：

- Base URL：`http://127.0.0.1:11434`。
- 模型名：与 `ollama list` 中的名称一致，例如 `qwen3:8b`。
- API Key：不需要。

点击「测试模型」，成功后可在翻译与从零写稿中使用。请使用本地模型；应用不会替你下载模型。

### 6. 配置在线模型（可选）

不安装 Ollama 也能使用在线翻译与完整 AI 写稿。先在相应服务商开通模型并取得 API Key，在 CutTools 的设置中填写：

| 服务商 | 默认 Base URL | 模型字段 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com` | 默认 `deepseek-flash`，或账号可用的模型名 |
| 千问 / 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 默认 `qwen-plus`，或账号可用的模型名 |
| 豆包 / 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | 控制台已开通的模型名或推理接入点 ID |
| 其他兼容接口 | 服务商提供的 HTTPS Base URL | 对应的文本模型名 |

API Key 输入后必须点击「保存 API Key」，再点击「发送测试请求」。千问的 Key 与地域需匹配；若使用业务空间专属域名，以控制台提供的地址为准。豆包的模型/接入点需先在控制台开通。密钥不要写入 README、源码或 Git 提交，也不需要设置在环境变量中；当前应用从 macOS 钥匙串读取它。

在线模式会把文案需求、素材文字或字幕与术语表发送至配置的服务地址，测试请求与正式调用都可能计费。不同服务商/地址的 Key 分别保存；修改 Base URL 后重新保存对应 Key。应用只支持 HTTPS、非流式文本 Chat Completions，不能直接接 Responses-only 或仅支持流式的模型。

### 7. 首次使用检查与常见问题

| 现象 | 检查方式 |
| --- | --- |
| 应用提示未找到 FFmpeg | 检查二进制是否在上述三个固定目录；仅修改 PATH 不够 |
| 安装了 FFmpeg 仍无法烧录 | 检查实际被应用找到的版本是否包含 `subtitles`；普通版与完整版的链接可能不同 |
| 提示 whisper-cli / 模型不存在 | 在 AI 字幕界面重新选择可执行文件及 ggml 模型，保存配置 |
| Ollama 无法连接 | 打开服务，检查 `api/tags` 与 `ollama list`，模型名必须一致 |
| 在线请求返回 401 / 403 | 检查已保存的 Key、服务地域及模型权限 |
| 在线请求返回 404 | 核对 Base URL 与模型名/接入点 ID |
| 在线请求返回 429 | 检查账户额度及调用频率 |
| 写稿模型未配置 | 可先生成无需模型的写作提纲，或配置一个在线模型 |
| FCPXML 提示素材离线 | 恢复原音视频文件的位置，或在 FCP 中重新链接媒体 |

应用设置、预设和文案草稿保存在本机用户偏好中，API Key 存在钥匙串。Git 克隆只包含源码、测试、图标与文档，不会带走这些配置；新 Mac 需要重新配置模型路径与密钥。模型权重、原始音视频、`.build/` 和 `dist/` 都不属于源码依赖文件。

## 音乐卡点（新增）

打开应用默认进入音乐卡点。导入 MP3/WAV/M4A 或带音轨的视频，点击分析节拍；算法在本机计算频谱突变、低频瞬态与能量变化，不需要 AI 模型。单次分析最长 30 分钟。

波形支持缩放和点击/拖动定位；播放时按 M 添加手动标记。点击候选时间从前方 0.3 秒试听；可逐帧微调、禁用或删除标记。强拍只是较强瞬态候选，能量转折候选默认禁用；BPM 是相邻候选间隔估计，可能出现半速/倍速，不能据此认定小节首拍。

导出 FCPXML 会创建带原音乐素材和标记的新时间线，需保留原音乐路径；默认 25 fps，可改为 24/30/50/60 fps。标记对齐所选帧率、排除禁用点，同帧标记合并。也支持 CSV 时间表与 JSON 标记工程保存/恢复；JSON 不包含音频和波形。恢复工程后重新分析会替换标记，执行前会确认。

FCPXML 标记结构参考 [Apple 标记说明](https://developer.apple.com/documentation/professional-video-applications/associating-ratings-keywords-markers-and-metadata-with-media)。XML 结构和帧边界测试通过，但尚未在 Final Cut Pro 内完成兼容验收。当前支持整数帧率；23.976/29.97/59.94 需要后续补充。

## 卡点筛选与从零写稿（新增）

卡点可按强拍、能量转折、强拍与转折、手动类型筛选；列表和波形同步显示。筛选不改变启用状态。使用「批量保留」可只启用指定类型，其他类型（包括手动点）会禁用但保留；可以撤销上一次批量操作。FCPXML/CSV 始终导出全部启用点，与当前显示筛选无关。恢复标记工程后可「恢复波形（保留标记）」，无需重新生成标记。

「从零写稿」填写主题、受众、目标时长、目的、风格和事实素材，使用已配置的本地或在线模型生成多个开头与完整的口播、镜头建议和屏幕文字。可选择模型、检查服务连接。只有成功且结构有效的结果才替换旧稿；失败或取消保留旧稿，再次生成会先确认。事实不足处要求模型使用待补充标记，生成内容仍需人工核实。

草稿与需求自动保存在本机；支持 Markdown 导出、复制口播稿、JSON 工程保存和载入。口播时长按每秒约 3.5 字估算，实际以朗读为准。未安装本地模型时可生成写作提纲，方括号内容需要自己填写，不会伪装成 AI 初稿。AI 写稿接口通过本地与在线请求模拟测试，尚未用真实模型验收生成质量。

## 本地与在线模型 / 应用图标（新增）

通过 macOS 菜单「CutTools → Settings…」（快捷键 ⌘,）或写稿/翻译工作区的「模型与 API Key 设置」进入统一配置。翻译与写稿共用当前模型，切换服务商后分别记住各自的地址与模型名称：

- Ollama：本机 `/api/generate`，无需 API Key，沿用原先的本地模型名。
- DeepSeek：预设 `https://api.deepseek.com`、`deepseek-flash`；可按账号权限改模型。
- 千问：预设北京通用地址 `https://dashscope.aliyuncs.com/compatible-mode/v1`、`qwen-plus`。可换控制台提供的业务空间专属/地域地址，Key 必须匹配地域。请求关闭混合思考，以获得普通文本 JSON 输出。
- 豆包：预设 `https://ark.cn-beijing.volces.com/api/v3`；填写火山方舟控制台的模型名或推理接入点 ID。
- 其他兼容接口：填写 HTTPS Base URL、模型与 Key，使用 Chat Completions 协议。

输入 API Key 后点击「保存 API Key」，密钥存储于系统钥匙串，按服务商与完整 Base URL 隔离，不写入偏好、文案/字幕或导出工程。编辑地址后需要重新保存对应 Key。在线生成会将待处理文本发送至设置中的地址，可能产生费用；不会自动上传音视频。在线连接测试也会发送一条短模型请求。

可选 JSON 模式仅适用于支持 `response_format=json_object` 的模型，默认不强制开启。仅支持非流式文本 Chat Completions；仅流式模型及 Responses-only 接口不适用。支持清除代码围栏、识别空结果/截断、鉴权/额度错误和取消，不会在失败时提交不完整译文或覆盖旧稿。在线请求禁止 HTTP 与重定向。

图标源文件在 `Assets/AppIcon.png`，包含音频波形和卡点标记；完整 iconset 与 `AppIcon.icns` 同目录保存，构建脚本会复制到应用 Resources 并配置 Info.plist，启动时设置 Dock 图标。

接口预设参考 [DeepSeek 官方文档](https://api-docs.deepseek.com/)、[千问官方兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[火山方舟官方 API Explorer](https://api.volcengine.com/api-explorer/?action=ChatCompletions&groupName=%E5%AF%B9%E8%AF%9D%28Chat%29+API&serviceCode=ark&tab=3&version=2024-01-01)。在线协议与错误处理已使用模拟响应验证，尚未使用真实 API Key 完成三家在线验收。

## 卡点排镜、局部改写、音乐对齐与模板

### 卡点排镜

1. 在「音乐卡点」导入并分析音乐，启用希望用于切镜头的点；强拍、转折或手动点都可以。
2. 打开「卡点排镜」，导入多个视频，设置音乐起止秒数、最短镜头长度，再点击「按卡点排镜」。范围最长 30 分钟，采用音乐工作区选择的整数帧率。
3. 素材按导入顺序轮换，可重复使用；太短的素材会跳过。如果没有足够长的素材，镜头显示未分配并禁止导出成片。素材列表可上移调整顺序。
4. 每个镜头可替换素材、修改素材入点并锁定。再次自动排镜保留锁定镜头；音乐/卡点变化导致原锁定区间不存在时，会要求先解锁。删除素材会清除相关镜头的分配。
5. 导出可编辑 FCPXML，或渲染前 10 秒预览/完整 MP4。MP4 统一 1920×1080、保留完整画面加黑边、H.264；保留选段音乐、关闭素材原声。FCPXML 使用 fit 适配，仍需在目标 FCP 中验证。

排镜工程自动保存到本机，也可保存/载入 JSON；未分配素材的工程可载入后继续调整。JSON 与 FCPXML 引用原文件，不包含素材。渲染在临时目录完成后才写入指定成片路径，取消或失败不会覆盖已有输出文件；源素材始终保留。

### 局部改写与版本对比

在「从零写稿」的每张镜头卡片点击「AI 改写」，选择精简、口语化、强化吸引力或增加故事感。改写使用当前统一模型配置，在线模型会发送当前段落、创作要求与事实素材，可能计费。

生成后先显示原文和建议对比，确认后只替换这一段的口播、画面建议和屏幕文字；段落 ID 和时长保持不变。原段落在等待期间被修改时，不会覆盖新内容。失败或取消保留原文。

顶部「版本」菜单可手动保存版本、查看历史与当前稿件对比、恢复旧稿。生成、应用改写和应用音乐节奏前会保存检查点；恢复前也保存当前稿件。保留最近 30 个版本，可随文案 JSON 工程一起导出。旧版本文案 JSON（没有镜头 ID 或历史字段）仍可载入。

### 文案与音乐对齐

在准备好文案并分析音乐后，点击「音乐对齐」。选择音乐范围（最多 600 秒）、重点段落、强拍或转折锚点及段间留白，生成对齐方案：重点段落对齐指定锚点，其他段落按原时长比例分配，并在允许范围内靠近已启用的卡点；结果显示开场、铺垫/展开、重点、收束及留白空镜。

可逐段试听，估算口播超时的段落会标为橙色。方案不会自动修改文本、配音速度或音乐速度。确认后可更新文案中的整数秒预计时长；精确到帧的时间和留白以导出为准。

支持导出 SRT（所选音乐片段从零计时）、CSV 分镜表，以及带原音乐选段和段落标记的 FCPXML。也可将段落起点添加为音乐卡点中的手动标记，不删除已有标记；若希望只按文案切点排镜，可在音乐卡点中使用「批量保留 → 仅启用手动标记」。默认口播估算为每秒约 3.5 字，需要按实际朗读核对。

### 个人创作模板

在创作需求面板的「模板」菜单使用旅行分享/知识口播预设，或把当前受众、目的、时长、语气和其他写作要求保存为个人模板。模板不包含主题、事实素材、API Key；应用模板也不会覆盖当前主题与事实素材。

个人模板保存在本机，支持 JSON 导入/导出；同名模板自动加序号。模板用于复用创作习惯，不会直接替换已有稿件。

### 本轮验证范围

## 双轨标题、FCP 设置与实时字幕预览

在「工具箱 → 字幕样式」中导入视频和中英文字幕，播放视频或使用「定位字幕」检查对应画面。字幕按当前播放时间出现、消失；调整字号、颜色、水平偏移和距底边距离会即时更新。预览和 FCPXML 共用字体换行计算；HDR 亮度与 FCP 模板的实际渲染以 FCP 为准。预览保留原画面并适配所选输出比例，不模拟裁切、模糊背景等视频处理。

- 中文与英文分别使用独立标题轨和语言角色，各自保留原字幕时间，不再拼成一个标题文本框。可分别设置样式、位置，或恢复自动上下排版。长句按输出宽度换行；出现多行重叠时可提高上方语言的距底边距离。
- 帧率支持 23.976、24、25、29.97、30、50、59.94、60 fps。分数帧率使用 1001/24000 等精确帧时长，所有标题起止时间对齐到帧；不足一帧保留一帧。时间码显示使用 NDF。
- 分辨率支持自定义偶数尺寸与横竖屏预设，并与现有交付设置共用；调整后也会影响字幕烧录。颜色设置包含标准 Rec.709、广色域 HDR 资源库中的 Rec.709 项目、Rec.2020 HLG、Rec.2020 PQ。请匹配 FCP 的资源库和项目设置。
- 先在右侧选择保存目录，再点击「导出双轨 FCPXML」。FCP 使用「文件 → 导入 → XML」，打开「CutTools」事件中的「可编辑双语字幕」项目，再把标题复制到原视频时间线。无需再次将字幕转换为标题。

测试覆盖双轨独立时间和样式、所有帧率/颜色组合、竖屏尺寸、换行、旧样式兼容、无效输入、播放时间更新和叠加层清理；安装 FCP 时还会使用其 FCPXML 1.10 DTD 校验文档结构。实际 FCP 导入和 HDR 显示仍需实机验收。
